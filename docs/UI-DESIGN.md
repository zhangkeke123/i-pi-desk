## 0. 设计读数与三个转盘

**设计读数**（一句话）：*这是一个面向写代码的人、在**本机**里干活的常驻桌面工具，气质是「专业编辑器」而不是「聊天机器人」——底色安静、信息密度偏高、动效克制，颜色只用来表达状态而不是装饰。*

**三个转盘**（沿用 taste-skill 的记号）：

| 转盘 | 取值 | 理由 |
|---|---|---|
| `DESIGN_VARIANCE` | **3** | 这是**工具**不是作品集：布局要可预测，用户每天看几十次。位置记忆比惊喜重要 |
| `MOTION_INTENSITY` | **3** | 动效只承担「状态变化被看见」的职责（面板开合、流式、审批出现）。不做入场编排、不做滚动叙事 |
| `VISUAL_DENSITY` | **7** | 代码、路径、diff、token 用量都是高信息密度内容；留白要给内容让位，但不能挤到读不动 |

> **一个必须如实说明的边界**：taste-skill 自己在 §13 写明它**不适用于** dense product UI、dashboard、
> 以及**代码编辑器**（编辑器要用 CodeMirror/Monaco 自己的皮肤体系）。i-pi-desk 恰恰属于这一类。
> 所以这份设计**只借用**它三类对产品 UI 同样成立的规则：
> ① 重设计协议（先审计、后改，见 §11）；② 交互状态必须完整（空/加载/错误/按下反馈）；
> ③ 形状与颜色的一致性锁（一套圆角体系、一个强调色贯穿全局）。
> 它的营销页规则（hero 视口、logo 墙、bento 网格…）这里**不适用**，不硬套。

## 2. 信息架构

```
i-pi-desk 窗口（最小 900 × 600）
├── 左：会话栏 aside 264px 固定
│   ├── 品牌头（可拖拽）
│   ├── 工作区切换行（当前目录 + chevron）
│   ├── 主行动：新建会话（全宽）
│   ├── 搜索（会话 > 4 时出现）
│   ├── 会话列表（按当前目录过滤；当前项左侧强调条；待确认徽标）
│   ├── 最近目录（> 1 时出现）
│   └── 底部：模型与设置
├── 中：主区（自适应）
│   ├── 顶栏 48px：工作区名 + 路径 · 内核状态 · 主题 · 终端 · 技能 · 文件 · 设置
│   ├── 消息流（max-w-3xl 居中，独立滚动）
│   └── 输入区（固定在底部）
└── 右：工作区面板 288px（可开合）
    ├── 文件树（标题栏 + 新建/刷新/收起）
    ├── 文件预览/编辑器（模态或面板内）
    └── 终端 288px 高（底部停靠，可开合）
```

**三条结构性决定**（都不是随手定的）：

1. **终端在底部、文件树在右侧、会话在左侧**：终端占垂直空间（读代码时横向宽度更贵），文件树按需出现（不用时不该吃掉对话宽度）。这与「左导航 / 中内容 / 右上下文」的通用分栏一致，但**没有**做成可拖拽的自由布局 —— 可拖拽的代价是每次都要重新摆，而这是每天开几十次的工具。
2. **消息流整宽、agent 消息是卡面、用户消息是右对齐气泡**：agent 的输出里会嵌 diff 与工具卡，窄气泡会把 diff 挤坏。
3. **所有面板共用一套 `.panel` 外壳**（38px 头 + 标题 + 动作），这样「哪一块是什么」在任何位置都一致。

## 3. 状态矩阵（这份设计的核心）

每个状态都按同一张表来定：**它回答用户的哪个问题 → 界面上必须有什么 → 怎么验**。
「验法」一列区分**可自动断言**与**长会话的渲染窗口（§8-B 第 4 项）** —— 规则已实现且有 10 条单测；端到端只覆盖
「短会话不折叠 + 渲染数不超过上限」，**长会话正面路径未覆盖**：补法已定位
（自测里那一段要放在应用重启**之前**，或改用重启后的 CDP client ——
第一版放在重启之后又用了旧连接，于是卡在永不返回的 await 上）。详见 ARCHITECTURE §15.21。

**只能人眼**

> **两处诚实的覆盖缺口**：
>
> ① **max_steps 的正面路径**（真的撞上之后那句话出现在界面上）目前没有任何自动化覆盖：
>    它需要一个**连续多轮调用工具**的假模型，而现在的假模型一轮就结束 ——
>    界面层与 host 层都试过，最后确认「撞不到」是内核语义（maxSteps 计**模型轮数**）导致的。
>    文案本身（带具体步数、指向设置位置）由单测覆盖，「不该常驻」由 verify:renderer 覆盖。
>    补法已知：给假模型加一个「连续 N 轮调用工具」的模式。
>
> ② 限额预警（80% 提醒）—— ✅ **已覆盖**：给假模型加了 `@loopN` 连续工具调用模式（4 次工具调用 + `maxSteps=5` = 正好 80%），端到端 5 条断言（预警出现、带「4/5」、说清是「接近上限」、有入口、改回不留副作用）。详见 ARCHITECTURE §15.23。
>
> 下面这些是「只能人眼」的项 —— 上面两条则属于「知道怎么补、还没补」。
> 端到端要驱动 40 步、或把 maxSteps 调到 1 再容忍一次必然中断的运行，代价与风险都不划算。
>
> **只能人眼**——这是本项目一贯的分工。

### 3.1 空（第一次打开 / 新会话）

*回答的问题：这里能干什么？*

**必须有什么**

- 一句用**用户的话**说的用途（不是模型的话）：「本地优先的 AI 编程工作台」。
- **3 个可点的起手任务**，点了填进输入框（不是替你发送）。
- **从当前上下文生成的**起手任务：选了工作目录后，示例应基于**这个目录的真实情况**（有 `package.json` → 「跑一遍测试并修报错」；有 `src/` → 「带我过一遍项目结构」）。没选目录时示例置灰并说明原因。
- **能力清单**（4 条）：读写文件 / 执行命令 / 差异视图 / 技能与插件，每条一句实话（例如「危险命令即使自动模式也会问」）。
- 焦点默认在输入框；快捷键提示常驻在输入区底部。

**验法**：可自动（示例条数、点击后文本进了输入框、未选目录时置灰）。「新用户能否两分钟内完成一次有用任务」只能人眼。

### 3.2 思考（已提交、还没有可见输出）

*回答的问题：它在转吗？在转什么？*

**必须有什么**

- 提交后**立刻**出现用户气泡与「agent · 生成中」，并且**禁止重复提交**（输入区置为等待态）。
- **1–2 秒内**把「生成中」升级成**说人话的步骤**：`正在读取 src/main.ts` / `正在运行 pnpm test` —— 这直接由工具调用事件驱动，不需要额外猜测。
- 超过 **10 秒**：显示**已用时长**，并把「停止」保持在最显眼的位置。
- **每一次运行都必须落到**：结果 / 可重试的错误 / 一句解释。**没有出口的思考态是设计事故**。

**现状**：部分已有（停止按钮、工具卡会显示状态），**缺**「生成中」的步骤化与计时。

**验法**：可自动（1/10/60 秒三个时间点上截图，各自的文案非空且停止可见）。

### 3.3 流式（输出正在到达）

*回答的问题：能读了吗？能停吗？*

**必须有什么**

- 发送按钮**变成停止**（已有的做法正确：开始请求的控件就是结束它的控件）。
- 停止后**保留已到达的内容**。
- 用户往上滚时**停止自动滚动**，回到底部才恢复（已有）。
- 为迟到元素**预留空间**：代码块、表格、diff 的高度不要跳（标记为待做：给 `pre`/表格一个最小高度并按内容增长）。
- 结束要**无歧义**：停止变回发送，出现「复制」；这条消息的 token 用量与耗时出现。
- 屏幕阅读器**只播报开始与结束**，不逐 token 播报（待做：`aria-live="polite"` 只放在状态行上）。

**验法**：可自动（流式中按钮 title=中止、结束后 title=发送、滚上去后 scrollTop 不变）。

### 3.4 部分完成（多步任务里有的成功有的失败）

*回答的问题：做完了哪些？没做哪些？*

**必须有什么**

- **结论先说数字**：「8 步里完成了 6 步」。
- **逐个列出没做的**，每条带原因（失败/被拒绝/超时）。
- **保留已完成的工作**；「重试」只重跑失败的那几步（不重复已有副作用）。
- 说明**有没有留下不一致状态**（例如「文件已改但测试没跑」），以及怎么收拾。
- 留一个**可续的位置**（会话本身就是这个位置：重开这个会话就能接着问）。

**现状**：`max_steps` 与 `aborted` 有提示，但没有「部分完成」的汇总。

**验法**：可自动（构造一个 6 成功 2 失败的 run，断言汇总里的数字与失败列表）。

### 3.5 错误

*回答的问题：哪儿坏了？我的东西还在吗？*

**必须有什么**

- 说清**是什么**（用能懂的话）以及**重试有没有用**。
- 明确**什么被保住了**：输入、之前的输出、磁盘上的文件（本项目的强项：改动都要过审批与 diff）。
- **一个主要恢复动作**：重试 / 去配置 / 重新加载。
- 凡是 agent 改过文件，**给一个回滚点**（现状：靠 diff 预览 + 系统回收站；**待定**：是否需要「本会话的检查点」——这属于功能范围变更，见 §8 的开放问题）。
- 错误码与日志**次要**呈现（已有：设置里「关于」+ 主进程日志）。

**反模式（明确不做）**：请求失败时清空输入框；「出错了」但不说下一步；悄悄自动重试并重复副作用。

**验法**：可自动（断网/返回畸形工具结果/厂商 500 三种注入，断言输入还在、恢复动作唯一）。

### 3.6 拒绝（政策 / 能力 / 权限三种「不」）

*回答的问题：为什么不行？那我能做什么？*

**必须有什么**

- **一句话说不**，不说道理、不说教。
- **点明是哪种不**：
  - **权限**（本机最常见的）：需要你确认 / 权限模式是「只读」→ 给出「切到每次询问」的入口；
  - **能力**：这个工具不在本次生效的工具集里（例如插件没启用）→ 指出怎么启用；
  - **政策**：厂商侧拒绝 → 原样转述厂商的话，别自己加解释。
- **给出最近的替代**；能做的部分**继续做**。
- 允许用户标记「这个拒绝看起来不对」（待做）。

**现状**：审批里的「拒绝」是**用户**拒绝 agent，与这里的「被拒绝」是两件事 —— 设计上要区分措辞（前者「你拒绝了这次操作」，后者「这一步被拒绝了，原因是…」）。

**验法**：可自动（三种拒绝各构造一次，断言文案里点明了类型且都有下一步）。

### 3.7 交接（把活交给别人/别的工具）

*回答的问题：现在是谁在干活？它知道我说过什么吗？*

本项目的「交接」有三个具体形态：

1. **交给用户自己**：agent 要求授权 → 卡片上必须写清**要做什么、动哪个文件、影响几行**（已有：预览 diff + 工具名 + 参数）。
2. **交给终端**：agent 不碰终端（设计如此），用户想自己敲命令时开终端 —— 交接点是**当前工作目录一致**（已有）。
3. **交给插件**：插件工具的调用与结果也走同一套工具卡（已有，视觉上不加区分，因为对用户而言「都是它调的工具」）。

**验法**：可自动（审批卡必须含 工具名 / 预览 / 三个动作；终端 cwd 与会话 cwd 一致）。

### 3.8 限额与边界

*回答的问题：什么时候能继续？*

**必须有什么**

- **在撞墙前提醒**：`maxSteps` 用量在接近上限时（例如 ≥ 80%）在输入区上方出现一行细提示。
- 撞墙时说清**具体时间/条件**（「已达本次运行的最大步数 40」）以及**怎么调**（设置里的入口，已有）。
- **说明什么还能用**：历史、文件、已生成的 diff 都还在；可以直接发下一条。
- **保住进行中的工作**：绝不因为限额清空输入或会话。
- 上下文超限时说明「这条消息被截断了多少」（现状：历史重放有上限 40 条 / 60000 字符，但**界面没说过**——待做）。

**验法**：可自动（把 maxSteps 设为 1，断言提示文案里含具体数字与设置入口）。

## 5. 交互规格

### 5.1 首次运行（目标：两分钟内完成一次有用的事）

```
打开 → 空状态（未选目录）
   ├─ 主按钮「选择一个工作目录」→ 系统目录选择器
   ├─ 次按钮「配置模型 provider」→ 设置（控制面/预置/自定义）
   └─ 起手任务置灰 + 一句「选好工作目录后，可以这样开口」
选好目录 → 起手任务变为可用（基于该目录生成）→ 点一条 → 文本进输入框、焦点在输入框
有 provider？ ── 否 → 输入区上方一行：「还没有可用的模型，去配置 →」（可点）
             └─ 是 → 回车发送
```

**硬规则**：**发送按钮永不在「什么都没说清」的情况下禁用而不解释**。
若因为「没有工作目录」或「没有可用模型」而不能发送，输入区上方必须有一行说明 + 一个入口 ✗
（这是参考材料点名的反模式，也是本项目现阶段真实存在的缺口：未选目录时输入框仍可输入，回车后才报错）。

### 5.2 对话 + 工具 + 审批（主循环）

```
输入 → 回车（Shift+Enter 换行；↑/↓ 在单行时翻历史）
     → 用户气泡 + agent 行「生成中」+ 发送变停止
     → 工具卡出现（等待授权 → 执行中 → 完成/失败/已拒绝）
         └─ 需要授权时：审批卡在消息流内**就地展开**（不弹窗，目标就在眼前）
              ├─ 仅允许这一次  → 立刻执行
              ├─ 本会话内始终允许（相同参数） → 执行，并说明范围
              └─ 拒绝 → 卡片转为「已处理：拒绝」，run 继续（agent 收到拒绝原因）
     → 完成后：最终消息落在流里，输入区恢复
```

**必须在场的东西**：审批卡的倒计时（默认 5 分钟超时）+ 一句「超时会怎样」（超时按拒绝处理）。
**语言规则**：所有按钮文案都说**范围**（「相同参数」而不是「这个工具」）。

### 5.3 文件与编辑器

```
文件树点文件 → 预览模态（只读、语法高亮、可切换并排 diff）
    └─ 「继续编辑」→ 打开编辑器 → 脏标记 ● 未保存
        └─ Ctrl+S 保存（保存前校验文件是否被 agent 改过）
        └─ 关闭时若有未保存改动 → 就地确认（丢弃 / 继续编辑）
```
**跨面板一致**：删除文件走系统回收站并在文件树内就地确认（已有）；终端里的删除**不经**这套确认 ✗ 这是已知的边界，设计上不假装它被管住了（在能力清单里写明）。

## 6. 动效规格

| 场景 | 时长 / 缓动 | 备注 |
|---|---|---|
| 颜色/hover 变化 | 120ms `--ease-out` | 只改颜色，不改布局 |

| 审批卡出现 | 180ms 高度 + 300ms 强调色左条 | 左条是「这里需要你」的信号 |
| 列表增删（会话、文件） | 150ms（若引入 auto-animate，59KB） | 现状：无动画，可接受 |
| `prefers-reduced-motion: reduce` | 全部压到 1ms | 已有 |

**规则**：动效只用于「状态变化被看见」，不做入场编排、不做滚动叙事、不做无限循环装饰 ✗。

### 11.2 值得学的六点（都已并入 §8 的差距清单）

1. **空状态用用户自己的上下文打招呼** —— 它写「今天想在 **a3-lib** 里做点什么？」，一句话就把「这是你的项目」说清了。
   本项目现在是通用标题 ✗ → 改成「今天想在 **<工作区名>** 里做点什么？」，并在下面接起手任务。
2. **推理强度放在发送前** —— 它的输入区能直接看到 `deepseek-flash · medium`。本项目只显示模型与权限模式 ✗
   → 若内核支持（待核 pi-ai 的 reasoning 配置），把**思考强度**也做成发送前可见的 chip；不支持就说明为什么不放。
3. **会话按时间分组**（昨天 / 近 7 天）+ 「加载更多」 —— 会话一多就靠它撑住可读性。本项目是平铺 ✗ → 加分组与「加载更多」。
4. ~~快捷键要有设置页，并在 tooltip 里露出~~ **已实现**（键盘地图） —— 它连侧边栏开关都写了 `Ctrl+J`。本项目 §5.4 的键盘地图应从「提议」变「落地」，
   并统一在 `title` 里带上快捷键。
5. ~~Alt+Space 式快速启动~~ **已实现**（Ctrl+K） —— 把「打开某个面板 / 某个插件」变成一个键盘动作，而不是去角落里找图标。
   本项目的候选是 `Ctrl+K`（聚焦输入框）与一个面板启动器，见 §5.4 与 §10 的开放问题。
6. **空状态里放一个吉祥物/图形标识** —— 它的首屏比「一行灰字」友好得多。本项目用的是图标块 + 能力清单 ✓（这点我们更强），
   但可以把能力清单的图标换成一套更连贯的图形语言。

### 11.3 不该抄的五点

1. **会话列表里出现三条同名「新建任务」** ✗ —— 看起来像未完成状态，用户分不清哪条是哪条。
   本项目的标题取自首条用户消息 ✓，要守住这条：**列表里不出现无法区分的占位标题**。
2. **底部一排四个无标签图标**（设置/扩展/定时/通知）✗ —— 只有 tooltip，发现成本高。
   本项目用带文字的「模型与设置」+ 顶栏图标各带 `title` ✓，保持。
3. **输入区一次摆五个控件**（＋ / 智能体 / 全自动 / 模型 / 强度）✗ —— 正是参考材料点名的「一排模式按钮挡住第一次发送」。
   本项目的输入区只放**与这次发送直接相关**的两个（模型、权限模式），其余进设置 ✓。
4. **主区几乎全空**，没有任何能力提示 ✗ —— 新用户不知道它能干什么。本项目的四张能力卡正是补这个 ✓。
5. **自绘窗口控制（最小化/最大化/关闭）** ✗ —— 视觉上更「应用」，但放弃了系统级的可访问性与一致性，且要自己维护。
   本项目用系统边框 ✓，这是刻意的取舍。

### 11.4 一条结构性结论

上游把「能装多少插件」当成产品主轴（知识图谱、仓库百科、浏览器驱动…），**本项目刻意不做能力目录** ✓
（`HANDOVER` §3 已列）。这次对照反而确认了这条边界是对的：那些能力的**代价**是每个都要维护、
要解释、要在限额与审批里各有一套说法；而我们的目标只是「把本机编码这一件事做顺」。

**因此本设计的方向不变**：不追能力数量，把八个状态做完整、把每一次等待都有出口、把每个「不」都说清下一步。

## 12. 已落地（v2）：现在实际长什么样

> v1 定义的是**结构与交互**（§2–§7），v2 改的是**视觉语言**。这一节记录 v2 的真实取值、
> 为什么这么定、以及覆盖到哪一层。代码对应 `apps/desktop/src/styles.css` 的令牌，
> 过程与验证见 [ARCHITECTURE](./ARCHITECTURE.md) §15.24–§15.26。

### 12.1 这一版要修的是什么

拿界面和 taste-skill 的「LLM 默认审美」清单对了一遍，**中了四条**：
`Inter + slate-900`、统一的圆角卡片、居中的 hero、三/四张等宽能力卡。落到代码上是六个症状：

| 症状 | 改之前 | 改之后 |
|---|---|---|
| 冷色近黑 | `oklch(0.16 0.012 255)`（偏蓝） | `oklch(0.165 0.006 70)`（暖炭黑，色相 70° ≈ 棕） |
| 「AI 蓝」强调色 | `oklch(0.7 0.15 250)`，按钮/chip/图标块都在用 | **琥珀/铜** `oklch(0.72 0.128 62)`，**只用于状态**（运行中 / 等待确认 / 焦点环 / 危险） |
| 用阴影造层次 | `--shadow-sm/md/lg` 到处都是 | 近乎不投射（`0 1px 0`）——层级交给 1px 边框与底色差 |
| 圆角只有一档 | 几乎所有东西都是 10px 派生 | **5px**（更硬、更像工具；派生用 `max()` 兜底，避免基准调小后算出负值） |
| 字体是默认脸 | Inter Variable（296 KB） | **Geist**（76 KB）+ JetBrains Mono 承担结构信息 |
| 空状态像营销页 | 居中 hero + 图标色块 + 三张卡片 + 四宫格能力表 | **左对齐工作台**：一句话 + 一个动作 + 一列安静的起手任务 |

依据是两份真实设计规范（读了全文）：**Warp**（底色要暖、彩度极低、边框代替阴影、字重克制）
与 **Ollama**（零彩色、零阴影、字重不超过 500）。共识是：**AI 味的根源是「冷 + 亮蓝 + 阴影 + 什么都圆一点」**。

### 12.2 行动色：主行动不用强调色

新增一组令牌 `--color-action / -hover / -ink`：**深色主题 = 暖白底深字，浅色主题反过来**。
主按钮（新建会话 / 切换工作目录 / 发送）全部走它，于是**整屏唯一的彩色只剩状态**。
这一条是「不像 AI 生成」里最有效的一步 —— 上游那张图里唯一的高对比元素也是发送键，且完全不带彩色。

### 12.3 五套主题

| id | 一句话 | 强调色 |
|---|---|---|
| `midnight`（默认） | 暖炭黑，长时间盯屏不刺眼 | 琥珀/铜 |
| `graphite` | 中性深灰 + 苔绿，最紧凑（圆角 4px） | 苔绿 |
| `daylight` | 暖白浅色，白天用 | 深琥珀 |
| `paper` | 米黄纸，长时间阅读舒服 | 铜 |
| `contrast` | 高对比（无障碍取向）：纯黑底、纯白字、粗边框（圆角 2px） | 亮琥珀 |

**id、亮暗、数量都没变** —— 持久化的主题偏好不能因为换皮而失效（`verify:doc-claims` 会盯着两边不漂）。

### 12.4 主界面的四条规则

1. **空状态是工作台，不是欢迎页**：左对齐；大而轻的问候（26px、Regular，不是 Bold）+
   一行说明 + 一个该做的动作 + **一列安静的起手任务**（依据用等宽小字靠右：扫到几个源文件、有没有 README）。
   起手任务保留，是因为它带着「只有看过你项目才知道」的证据 —— 但它不该用三张卡片和小节标题把自己喊出来。
2. **控件贴着输入框下沿**：左侧是「这一次怎么跑」（模型 / 权限 / 思考强度三个 chip），
   右侧是**圆形发送键**；快捷键提示在字段**外面**。字段里只留控件。
3. **强调色只留给状态**（§12.1）。
4. **结构信息走等宽**：路径、计数、状态标签、小节标题（大写 + 0.14em 宽字距）——
   让字体分工表达层级，而不是靠彩色图标块。

### 12.5 设置：整窗面板（不再是弹窗）

h-12 标题栏 + **228px 左导航**（搜索框 + `偏好 / 智能体` 分组 + 图标）+ 右侧行式内容
（标签在左、控件在右、分组只靠小号灰标题 + 间距）。

- 点导航项是**滚动定位**到锚点，**不切换子页** —— 所有控件始终在 DOM 里
  （端到端依赖「打开设置后第一个 number 输入框是单次最大步数」这类事实），搜索也能直接命中任意一行。
- **枚举用分段控件**：权限模式是三档一排（完整说明进 `title` 与行说明，一个字没丢）。

### 12.6 侧栏 IA

顺序：**工作区切换 → 新建会话 → 会话（置顶 / 今天 / 昨天 / 近 7 天 / 更早）→ 项目 → 最近目录**。

- **置顶**：会话自带 `pinned`（跟着会话文件走）；单独成一组、**排在时间分组之前**；
  行内悬停出现图钉，已置顶的行**常显**（否则取消置顶要先去找 = 藏起来）。
  两条写进代码并被单测钉住的约定：**置顶不改时间序**（否则会出现「刚置顶就跑到今天那组最上面」而时间还是旧的）、
  **置顶不参与分页**（置顶的意义就是永远看得见）。
- **加载更多（N）**：默认显示 30 个，其余折叠。
- **项目**：别的目录里、**确实有会话**的目录（点一下切目录 + 打开那边最近的会话）。
  这里有一处**刻意偏离**：会话列表仍按当前目录过滤 —— 一个目录若已从「最近目录」移除，
  它下面的会话不会混进列表，只在「项目」里出现（并保留一行提示说明「其它目录还有 N 个会话」）。
- 小节标题统一成**等宽大写宽字距**。
