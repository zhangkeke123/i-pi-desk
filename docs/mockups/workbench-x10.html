产品判断（多年做 Agent 工作台的结论）

项目 = 容器

  • 一个本地目录 / 仓库 = 一个项目
  • 管：路径、颜色、会话集合、项目摘要
  • 不承载聊天，不做第二种会话列表

会话工作台 = 驾驶舱

  • 一次只深挖一个会话
  • 管：对话、Composer、审批、右侧产物
  • 列表必须可读：类型 + 状态 + 一句话总结 + 时间
  • 关系：项目 1 → 多会话；会话必属项目（「临时」= 默认工作区这个特殊项目）。
  • 导航：左轨「工作台」进驾驶舱；「项目」进容器总览。日常 80% 时间应停在工作台。
  • 列表组织：临时 → 置顶 → 按项目折叠；不要一锅乱时间轴。
默认推荐落地路径：以 A（会话优先） 为底盘，右栏按需常驻取自 E，项目页用 B 的摘要表，窄屏可叠 I 的摘要条。 多仓库重度切换再考虑 F；任务感强再加 G；命令党用 H。不要一上来做 D 收件箱（数据模型未成熟时会空）。
